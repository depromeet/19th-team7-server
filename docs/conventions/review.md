# 코드 리뷰 룰

리뷰어가 빠르게 읽고, 작성자가 코멘트의 무게를 바로 알 수 있도록 PR 크기와 코멘트 중요도를 맞춘다

## 작은 PR 규칙
- PR 하나의 변경량은 **1,000줄을 넘지 않는다**
  - 테스트 코드는 줄 수 계산에서 제외한다
- 200~300줄 안팎을 권장한다
- 1,000줄을 넘을 것 같으면 기능 단위로 PR을 나눈다
  - 예: 엔티티·리포지토리 → 서비스 → 컨트롤러 순으로 분리

## 코멘트 중요도 (Pn 룰)
리뷰 코멘트 맨 앞에 `[P1]` ~ `[P5]`를 붙여 반영 강도를 표시한다

| 표기 | 의미 | 리뷰 상태 | 작성자 대응 |
|---|---|---|---|
| `[P1]` | 꼭 반영해 주세요 | Request changes | 반드시 수정한다. 그대로 두면 장애나 심각한 오류로 이어질 수 있는 문제 |
| `[P2]` | 적극적으로 고려해 주세요 | Request changes | 수정하거나, 반영하지 않는다면 근거를 들어 리뷰어와 논의한다 |
| `[P3]` | 웬만하면 반영해 주세요 | Comment | 수정하거나, 반영하지 않는 이유를 답하거나, 이슈로 남겨 나중에 반영한다 |
| `[P4]` | 반영해도 좋고 넘어가도 좋아요 | Approve | 작성자가 판단한다. 답글 없이 넘어가도 된다 |
| `[P5]` | 사소한 의견이에요 | Approve | 무시해도 된다 |

- 예: `[P2] 이 조회는 반복문 안에서 매번 실행돼서 N+1 문제가 생길 수 있습니다. fetch join을 고려해 주세요`
- P1·P2 코멘트가 모두 해결되기 전에는 merge하지 않는다
